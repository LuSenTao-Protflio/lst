# 项目页导航与联系页脚设计规范

## 目标

解决进入项目详情页后停留在旧滚动位置、项目页缺少联系入口、只能前往下一个项目，以及返回目录入口占用内容导航位置的问题。

## 路由滚动

- 每次 React Router 的 `pathname` 发生变化后，将页面滚动到顶部。
- 首页的锚点跳转保持原有行为；从悬浮目录按钮返回时使用 `/#directory`，应落到 Projects 目录。
- 浏览器前进或后退进入不同项目时同样回到页面顶部。

## 项目循环导航

- 创建共享 `ProjectPager` 组件，供 WOOF-WOOF、MetaKeys 与共享编辑式项目页使用。
- 左侧显示“上一个项目”和上一个项目标题。
- 右侧显示“下一个项目”和下一个项目标题。
- 项目顺序按现有 `projects` 数据数组计算，形成循环：01 的上一个是 07，07 的下一个是 01。
- 标题跟随当前中英文语言切换。
- 移除三个详情模板中原有的“返回全部项目”链接与各自硬编码的下一项目链接。

## 返回全部项目悬浮按钮

- 创建共享 `AllProjectsButton`，仅在项目详情页渲染。
- 固定在页面右下角，桌面端为 56px 荧光黄圆形按钮，移动端为 48px。
- 默认显示 2×2 四格目录图标；悬停或键盘聚焦时显示“全部项目 / All Projects”提示。
- 点击返回 `/#directory`，进入首页项目目录而不是首页首屏。
- 使用 `aria-label`，具备清晰 focus 状态。
- 层级低于全局鼠标覆盖层但高于页面内容，不遮挡项目底部导航文字。

## 共享求职页脚

- 将首页现有“求职联系 / 邮箱 / 关于我”提取为 `SiteFooter` 组件。
- 首页继续使用相同组件，视觉与内容不变。
- 所有七个项目详情页在 `ProjectPager` 之后加入 `SiteFooter`。
- 页脚文案继续读取现有 i18n，不复制或建立第二份邮箱与介绍内容。

## 页面顺序

每个项目详情页统一为：

1. 项目档案与视觉内容
2. 上一个项目 / 下一个项目
3. 求职联系与关于我

悬浮“全部项目”按钮不参与文档流，始终固定在右下角。

## 响应式

- 桌面端项目导航两端对齐。
- 800px 以下仍保留左右两列，但缩小标题并限制宽度，避免变成长列表。
- 500px 以下可改为上下排列，上一个在前、下一个在后。
- 悬浮按钮使用 `right:max(1rem,env(safe-area-inset-right))` 和安全区域底部间距。

## 验证

- 从首页滚动到底部后进入任意项目，项目页从顶部显示。
- 连续点击上一个和下一个项目，顺序与标题正确且每次回顶。
- 七个项目页均显示共享求职页脚。
- 悬浮按钮返回首页 Projects 目录。
- 首页页脚内容与视觉没有回归。
- 全局自定义鼠标、点击圆环和所有链接仍正常。
- 生产构建通过且无横向溢出。
