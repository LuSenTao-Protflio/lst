# 全项目编号与 MetaKeys 详情页设计规范

## 目标

解决项目详情页中独立数字编号意义不明的问题，并根据 MetaKeys 九张素材的真实横竖比例，为其建立不裁切、不强制横版的编辑式项目详情页。

## 全项目编号

- 所有详情页统一显示双语项目编号：`PROJECT 01 / 项目 01` 至 `PROJECT 07 / 项目 07`。
- 字号使用约 16–18px 的响应式范围，采用半粗体和适度字距。
- 编号置于项目标签上方，视觉优先级低于标题、高于普通元信息。
- WOOF-WOOF 专用详情页与其余通用详情页使用同一格式。

## MetaKeys 页面结构

MetaKeys 使用专用详情组件，不修改其他项目的图片排版。

### 首屏

- 左侧使用横版包装图 `keycaps-03-packaging.jpg`，保持原始 2400×1647 比例。
- 右侧为项目档案：双语编号、标签、标题、中英文说明、项目类型、个人职责和项目时间。
- 桌面端采用与 WOOF-WOOF 一致的编辑式双栏语言，移动端改为单列。

### 图片叙事顺序

1. `keycaps-01-overview.jpg` 与 `keycaps-02-poster.jpg` 两张竖版并排。
2. `keycaps-04-lanyard.jpg` 横版全宽展示。
3. `keycaps-05-system.jpg` 作为较大竖版，`keycaps-06-product.jpg` 与 `keycaps-07-application.jpg` 组成辅助列，形成一大两小的错落组合。
4. `keycaps-08-scene.jpg` 与 `keycaps-09-render.jpg` 两张方形并排收尾。

全部图片使用自然比例，不使用固定横版容器、不裁切、不拉伸。

## 内容

- 保留现有 MetaKeys 项目标题、简介和标签。
- 补充三段不虚构商业结果的项目说明：品牌概念、模块化产品逻辑、视觉延展。
- 档案元信息注明项目类型、个人职责与年份。
- 页面结尾保留返回全部项目，并链接到下一个项目 FRIDAY 年会视觉。

## 响应式与动效

- 800px 以下取消 sticky，项目信息先于主视觉出现。
- 所有多列图片组合在移动端变为单列，保证竖版图片可读。
- 沿用现有轻微淡入位移动效，并尊重 `prefers-reduced-motion`。

## 边界与验证

- 不添加第三方依赖，不修改原始素材文件。
- WOOF-WOOF 页面继续使用现有专用布局；其他项目继续使用通用布局。
- 验证七个项目编号均为双语格式。
- 验证 MetaKeys 九张图片全部加载、无变形、无横向溢出。
- 验证生产构建通过。
